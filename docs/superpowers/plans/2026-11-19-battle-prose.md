# 소설형 전투 로그 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 실제 공방을 읽을 수 있는 소설형 로그를 전투 창과 생애 기록에 연결한다.
**Architecture:** 엔진의 선택적 사실 스냅샷 → 순수 서사 변환 → 합별 화면과 간결한 회고. 판정과 RNG는 유지한다.
**Tech Stack:** TypeScript, Preact, Vitest, Vite.
**Spec:** ../specs/2026-11-19-battle-prose-design.md

## Global Constraints
- 다른 작업의 수정은 보존한다. 전투 승패·난수·피해 수치를 바꾸지 않는다.
- 보유만 한 능력을 발동한 것처럼 쓰지 않는다. 실제 부상은 결과 처리 이전에 예고하지 않는다.

## 작업
- [x] 1. 판정 사실/시작 HP 및 순수 `combat/narrative.ts`를 테스트 우선으로 구현한다.
- [x] 2. `view/battle.ts`, BattleModal에 서사 기본 출력과 수치 보조 줄을 연결한다.
- [x] 3. 전투 종료 확인 후 생애 기록에 실제 사건 기반 회고를 남긴다.
- [x] 4. 실제 엔진·옛 저장·재생·미래 유출 검증, 화면 확인, 코드 리뷰와 빌드를 완료한다.

## Review Focus
나중에 켠 패기의 과거 소급, 회피를 명중으로 묘사, 회복 상한보다 큰 회복 주장, 시간 제한 판정승을 쓰러뜨린 승리로 묘사, 동료의 기본 공격과 협공 혼동을 검증한다.


## 검증 기록
- 기존 엔진과 시드 30개를 두 번 대조했다. 메타데이터를 제외한 기존 사건 필드·피해·HP·SP·결과·기술 사용량·난수 cursor는 동일하다.
- 첫 전체 검사: 827 통과, 3 실패, 5 todo. 세 실패는 공방 자료 없이 결과만 주입하던 paths/turning 테스트에서 회고를 생성하려던 원인으로 확인하고, 자료가 없으면 빈 회고를 반환하도록 수정했다.
- 수정 후 전투·화면·후속 처리 7개 파일 177개 테스트 통과. 별도 일반 회귀 실행은 54개 파일 819개 통과, 5 todo (sim.test.ts 제외)였다. 대량 sim.test.ts는 앞선 전체 실행에서 통과했으며 판정 변경이 없는 출력 수정 뒤 재실행하지 않았다.
- 코드 리뷰의 표시 줄 읽기 시간/옛 저장 회복량 문제를 재현 테스트 후 수정했다. 견문색의 실제 판정 기여, 회고 사건 순서, 미래 패기 상태 소급 방지를 검증했다.
- 데스크톱 1440px 및 모바일 500px Chrome 실제 화면에서 소설형 기본 출력과 11개 원본 사건의 보존 PASS. 임시 미리보기 파일과 QA 서버는 정리했다.
- 타입 검사·빌드 및 git diff --check 통과. 기존 번들 크기 경고는 남아 있다.
