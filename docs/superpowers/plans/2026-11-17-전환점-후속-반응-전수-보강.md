# 전환점 후속 반응 전수 보강 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 모든 선택형 전환점에서 선택 직후 실제 행동과 결과가 성향 변화보다 먼저 드러나게 한다.

**Architecture:** 현재 `Door.fx`의 `log`를 후속 장면의 근거로 사용한다. 확률 분기의 양쪽과 조건에 따라 이어지는 선택형 전환점까지 경로별로 검사한다. 장편 에피소드처럼 곧바로 전투나 다음 장면을 여는 선택지는 그 장면을 결과로 인정하고, 나머지는 해당 사건의 본문·힌트·효과와 맞는 대사를 직접 작성한다.

**Tech Stack:** TypeScript, Vitest, Vite.

**Spec:** 사용자의 2026-11-17 요청: “나머지도 문맥별로 검토하고 모두 수정해 필요하면 선택지로 인한 새로운 선택지도 작성해”.

## Global Constraints

- 기존 가치관 점수, 확률, 돈, 체력, 인연, 원작 시간선은 서사 보강만을 이유로 바꾸지 않는다.
- 확률 분기마다 실제로 일어난 일만 말한다. 실패와 성공을 같은 문장으로 처리하지 않는다.
- 새 선택지는 기존 문이 의도한 행동이 추가 결정 없이는 결론 나지 않는 경우에만 만든다.
- 기존 작업 중인 파일과 변경 사항을 보존한다.

## Review Focus

- 확률 실패에서 빈 기록으로 끝나지 않는가.
- 기존 힌트가 가능성만 말할 때 결과 문장이 성공을 단정하지 않는가.
- `queue`/`fight`처럼 다음 화면이 즉시 열리는 선택을 중복 서술하지 않는가.
- 선택 이후 결과 장면이 성향 문장보다 먼저 표시되는가.
- 원작 인물·장소·연령 조건을 어기는 후속 문장은 없는가.
