# v5 2단계: 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1단계에서 만든 v5 코어(`src/v5/core`) 위에 화면을 붙여, 개발 서버에서 로그타운의 한 인생을 태어나서 엔딩까지 직접 플레이할 수 있게 한다.

**Architecture:** 화면은 `src/v5/app`(저장, 흐름, 상태 보관)과 `src/v5/ui`(Preact 화면)에 새로 만든다. 시간의 흐름(기록 한 줄 띄우기, 다음 토막으로 넘기기)은 순수 함수 `nextTick`이 정하고, 화면에 나갈 말은 순수 함수(view)가 만들어 Node에서 테스트한다. 컴포넌트는 그 결과를 그리기만 한다. 픽셀 연출(`src/ui/pixel`), 소리(`src/app/sound.ts`), 스타일(`src/ui/styles/pixel.css`)은 v4 것을 그대로 쓰고, 마지막에 v5가 쓰지 않는 v4 코드를 지운다.

**Tech Stack:** TypeScript 7, Vite 8, Preact 11, Vitest 5 (DOM 없이 Node에서 실행).

**Spec:** `docs/superpowers/specs/2026-11-15-v5-갈래-인생-설계.md` (4.1 화면, 5.2a, 5.2b, 5.7, 5.8, 5.9, 7장)

**코드 위치에 대한 결정:** 설계 4.1은 `src/core/`를 새 코어로 바꾼다고 했다. v5 코어는 v4의 전투 엔진 · 난수 · 조사 · 데이터를 계속 가져다 쓰고, 파일 이름이 겹친다(`types.ts`, `state.ts`, `reduce.ts`, `balance.ts`). 그래서 폴더를 합치지 않는다. v5는 `src/v5/{core,data,app,ui}`에 두고, v4에서는 v5가 쓰는 파일만 남기고 나머지를 지운다(과제 10). 옛 버전 폴더처럼 통째로 복사한 폴더는 만들지 않는다는 설계의 뜻은 지킨다.

## Global Constraints

- 작업 가지는 `v5-life`. `main`과 태그 `v4.0.16`은 건드리지 않는다. 푸시하지 않는다.
- `src/v5/core/`는 DOM, 타이머, `localStorage`, `Math.random`, `Date`를 쓰지 않는다. 난수는 `rngOf(s.rng)`만 쓴다. (`src/v5/app`, `src/v5/ui`는 써도 된다.)
- 화면이 코어에 보내는 명령은 `step`과 `answer` 둘뿐이다. 상점, 수련, 편성 화면과 명령을 만들지 않는다.
- 가치관 점수(숫자)는 화면 어디에도 내지 않는다. 가장 높은 한두 가지를 말로만 적는다.
- 선택지 옆에 그 문이 올리는 가치관을 적지 않는다. "전에 골라 본 문" 표시만 한다. 문이 올린 가치관은 도감에서만 보인다.
- 기록에 달 표시가 없다. 한 해가 바뀌면 `열일곱 살 · 로그타운` 꼴의 구분선이 뜬다.
- 기록은 하나씩 떠오르고 저절로 이어진다. 정지와 배속(0, 1, 2, 4, 8) 버튼이 있다. 선택 · 싸움 · 엔딩 창은 기록이 다 떠오른 뒤에 뜬다.
- 저장 열쇠는 `gt5.life`, `gt5.meta`, `gt5.settings`. v4의 `gt4.*`는 읽지도 지우지도 않는다.
- 화면 폭 760px 이하는 휴대폰 배치다. 휴대폰과 데스크톱 모두 페이지 전체가 스크롤되지 않는다(칸 안에서만 스크롤).
- 변수를 넣어 만드는 한국어 문장은 `src/core/josa.ts`의 `josa()`를 거친다.
- 스타일은 `src/ui/styles/pixel.css`의 기존 클래스를 쓴다. 새 클래스가 필요하면 그 파일 끝의 `/* v5 */` 구역에 더한다.
- 테스트: `npx vitest run tests/v5`. 전체 확인: `npm run typecheck && npm test`.
- 커밋 메시지는 한국어로 쓰고 끝에 붙인다: `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`

## Review Focus

각 줄의 테스트는 괄호 안 과제에 들어 있다.

1. **옛 모양이거나 깨진 저장** — `gt5.life`에 칸이 빠진 인생이나 JSON이 아닌 글자가 들어 있어도 시작 화면이 뜬다. 빠진 칸은 기본값으로 채우고, 못 살리면 "이어 하기"를 내지 않는다. (과제 1, 2)
2. **기록이 잘려 나간 뒤** — 기록은 400줄만 남는다. 아직 못 본 줄이 잘려 나가도 흐름이 멈추지 않고 남아 있는 첫 줄부터 이어진다. (과제 2)
3. **멈춰 있어야 할 때** — 정지, 창이 열려 있을 때, 탭이 가려졌을 때, 읽는 중일 때는 시간이 흐르지 않는다. 정지한 채 새 인생을 시작하면 1배속으로 시작한다. (과제 2)
4. **인생이 끝나는 순간** — 못 본 기록이 남아 있으면 엔딩 창이 뜨지 않는다. 엔딩에서 새로 고침하면 엔딩이 다시 뜬다. 끝내기를 두 번 눌러도 명예의 전당에 한 번만 남는다. (과제 2, 8)
5. **길고 많은 선택지** — 문이 여덟 개이거나 본문이 길어도 휴대폰(375×812)에서 창 안에서 스크롤되고 모든 문을 누를 수 있다. 성이 없는 고아의 이름이 `null`이나 빈칸 없이 나온다. (과제 3, 6, 11)

```ts
describe('저장 읽기', () => {

    expect(fixed.known).toEqual([]);

    expect(normalizeLife5(bad)).toBeNull();
```

- `nextTick`의 규칙:
  1. `screen`이 `'main'`이 아니거나, 인생이 없거나, `modalOpen`, `reading`, `hidden`, `speed === 0`이면 `{ do: 'wait' }`.
  2. 못 본 줄이 있으면 `{ do: 'reveal', id, wait }`. `wait`는 **그 줄 다음에** 기다릴 시간으로, 방금 띄운 줄의 무게에 따라 `lineMs`(light) · `heavyMs`(heavy) · `yearMs`(year)를 `speed`로 나눈 값이다.
  3. 다 봤고 `pending`이 있으면 `{ do: 'wait' }` (창이 뜬다).
  4. 다 봤고 `pending`이 없으면 `{ do: 'step', wait: stepMs / speed }`.
- `store.ts`는 v4의 `src/app/store.ts`와 같은 짜임이다(구독, `set`, 타이머 `kick`/`schedule`, `visibilitychange`). 다른 점:
  - 타이머는 `nextTick`의 답을 그대로 따른다.
  - `newLife`는 `Date.now()`와 `performance.now()`로 씨앗을 만들고 `newLife5(seed, { name, gender, known: knownDoors(meta) })`를 부른다. 정지 상태면 1배속으로 바꾼다. `shownId`는 -1에서 시작한다(기록의 `id`가 0부터다).
  - 저장 시점: `answer` 뒤, 그리고 `step` 뒤에 나이가 바뀌었거나 `pending`이 생겼을 때.
  - `endLife`는 `pending`이 `ending`일 때만 동작한다. `recordLife(meta, life)`를 저장하고 인생을 지운 뒤 시작 화면으로 간다. 인생이 이미 없으면 아무것도 하지 않는다.
  - 불러온 인생은 이미 본 것으로 친다(`shownId = lastLogId(life)`).
  - 줄이 떠오를 때 소리: `heavy`는 `sfx('event')`, `light`는 `sfx('line')`, `year`는 소리 없음.

```ts
// tests/v5/flow.test.ts
import { describe, expect, it } from 'vitest';
import { CLOCK, caughtUp, estimateMinutes, lastLogId, nextHidden, nextTick, type FlowInput } from '../../src/v5/app/flow';
import { parseImport } from '../../src/v5/app/save';
import { autoplay5 } from '../../src/v5/core/autoplay';
import { newLife5 } from '../../src/v5/core/state';
import { emptyMeta5 } from '../../src/v5/core/meta';

const base = (over: Partial<FlowInput> = {}): FlowInput =>
  ({ life: newLife5(1), shownId: -1, speed: 1, screen: 'main', modalOpen: false, reading: false, hidden: false, ...over });

describe('흐름', () => {
  it('못 본 줄이 있으면 한 줄씩 띄운다', () => {
    const x = base(); const t = nextTick(x);
    expect(t).toMatchObject({ do: 'reveal', id: x.life!.log[0].id });
  });
  it('다 보고 선택이 떠 있으면 기다린다', () => {
    const x = base(); x.shownId = lastLogId(x.life);
    expect(x.life!.pending).not.toBeNull();
    expect(nextTick(x)).toEqual({ do: 'wait' });
  });
  it('다 보고 떠 있는 일이 없으면 다음 토막으로 간다', () => {
    const x = base(); x.life!.pending = null; x.shownId = lastLogId(x.life);
    expect(nextTick(x)).toEqual({ do: 'step', wait: CLOCK.stepMs });
  });
  it('정지, 열린 창, 읽는 중, 가려진 탭, 시작 화면에서는 흐르지 않는다', () => {
    for (const over of [{ speed: 0 as const }, { modalOpen: true }, { reading: true }, { hidden: true }, { screen: 'start' as const }, { life: null }])
      expect(nextTick(base(over))).toEqual({ do: 'wait' });
  });
  it('배속이면 기다리는 시간이 그만큼 준다', () => {
    const a = nextTick(base({ speed: 1 })), b = nextTick(base({ speed: 4 }));
    if (a.do !== 'reveal' || b.do !== 'reveal') throw new Error('reveal이어야 한다');
    expect(b.wait).toBeCloseTo(a.wait / 4);
  });
  it('무거운 줄은 더 오래, 해 구분선은 더 짧게 머문다', () => {
    expect(CLOCK.heavyMs).toBeGreaterThan(CLOCK.lineMs);
    expect(CLOCK.yearMs).toBeLessThan(CLOCK.lineMs);
  });
  it('못 본 줄이 잘려 나갔어도 남아 있는 첫 줄부터 이어진다', () => {
```
