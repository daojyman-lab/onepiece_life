# 특성 100종 확장 구현 계획

**Goal:** 기존 25개 출생·6개 후천 특성에 신규 100종을 더하고 최대 5개 적용, 획득, 상위 교체, 실제 효과를 게임 흐름으로 연결한다.
**Architecture:** v5 전용 데이터와 core/traits.ts가 보유·활성·획득·배율을 관리한다. 기존 특성 데이터와 소비 경로를 재사용하며 거래만 명시적으로 표시한다.
**Tech Stack:** TypeScript, Preact, Vitest.
**Spec:** 사용자 2026-11-18 구현 요청과 이 문서의 제약.

## Global Constraints
- 신규 100종, 단어형 이름. 정의·먹보·협응·지식·협상가 5%·달변가 10%를 포함.
- 기획한 출생 28종과 후천 8종 포함. 모든 데이터는 실제 소비 필드를 가진다.
- 출생 2~5개, 활성 합계 최대 5개. 해금 기록은 보존, 상위 계열은 중복 적용 금지.
- 협응은 건강한 동료 전투력 일부를 주인공에게 더하며 개인 능력의 20% 이하로 제한.
- 거래 할인은 명시한 거래 비용과 입장 금액 조건에 함께 반영. 보상·세금·벌금·기부는 원래 계산.
- 옛 저장은 정규화하며 출생 재추첨은 없음. 효과를 꺼도 원래 출생 능력치 보너스가 남지 않게 계산.
- 이번에는 특성 구현에 집중하며 앞선 비서약 성장 사건과 D급 10% 규칙은 포함하지 않음.

## Tasks
- [x] 1. 신규 특성 데이터 100개, 정의와 획득 조건을 만들고 개수·중복·효과 소비를 검사.
- [x] 2. 보유·활성·최대5·상위교체·저장 정규화 및 명령/UI를 연결.
- [x] 3. 출생, 선택, 활동, 거래, 회복, 영입, 전투, 항해에 획득과 효과를 연결.
- [x] 4. 구 특성의 미적용 효과를 연결하고 실제 거래를 표시. 핵심 회귀 테스트 실패→수정→통과.
- [x] 5. 전수 획득 검증, 표본 자동 플레이, 전체 테스트와 빌드, 독립 코드 리뷰 후 main 푸시·배포 확인.

## Review Focus
할인 뒤 금액으로 선택 잠금과 지불이 일치해야 한다. 재영입과 재선택으로 해금이 반복되지 않아야 한다. legacy 상태와 사망·부상 동료를 처리해야 한다. 비활성 특성과 상위/하위 특성이 효과에 새지 않아야 한다. 툴팁 수치는 데이터와 같은 값을 사용한다.
