# v6.9 주요 섬 시나리오 다양화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 주요 6섬의 이미 작성된 18개 스크립트에서 반복적인 조직·결말 구조와 원작 행적 충돌을 제거한다.

**Architecture:** 기존 전환점 ID와 파일 분리를 유지해 저장 데이터 호환성을 지킨다. 사건을 지역 규모로 좁히고, 원작 인물 직접 전투를 원작과 충돌하지 않는 지역 사건·목격·조사로 바꾼다. 결말은 섬마다 고유한 이해관계로 설명한다.

**Tech Stack:** TypeScript, Vitest, Preact 게임 데이터.

**Spec:** `docs/01_기획/09_주요_6섬_이야기_검토와_수정안.md`

## Global Constraints

- 원작의 승패·체포·생사를 바꾸지 않는다.
- 6개 섬마다 원작 전·그 무렵·뒤 중 방문 시기에 맞는 편 하나를 진행한다.
- 변경 전환점의 `id`, `next` 대상, 완료 표시는 저장 데이터 호환을 위해 유지한다.
- 주요 섬 체류는 기획상 8~12주이며 원작 사건 자체의 지속 기간으로 설명하지 않는다.

## Review Focus

- 보스전 승리·패배·회피 뒤에도 다음 장면이 이어지는가.
- 원작 그 무렵의 사건을 플레이어가 해결했다고 기록하지 않는가.
- 시점이 바뀌어도 원작 인물의 소재지와 소속이 맞는가.
- 각 편의 결말이 지역 주민의 구체적인 손익으로 이어지는가.
- `next`와 표시 조건이 기존 저장을 막지 않는가.
