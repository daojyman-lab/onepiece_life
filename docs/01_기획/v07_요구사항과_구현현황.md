# v7 요구사항과 구현 현황

2026-11-17 · 최초 조사 · 대상은 v6.9 작업 트리의 `src/app/main.tsx → src/v5/ui/App` 실행 경로다. 아래는 코드에서 확인한 기준선과 v7 제안이다. 신규 구현의 완료 증거는 각 ID에 추가한다. [v7 통합 기획서](v07_doc.md)

## 1. 기록 방법

**최종판에서 필요한지**와 **어디까지 구현됐는지**를 별도로 적는다. 최종판 범위는 기존 합의, 포함 제안, 보류, 대체로 표시한다. 구현은 미연결, 부분 연결, 구현 확인, 검증 완료로 구분한다. ‘구현 확인’은 실행 경로를 찾았다는 뜻이다. ‘검증 완료’에는 대상 빌드, 실제 진입 방법, 통과 결과가 필요하다. 장면 원고, 데이터 추가, 단위 테스트 통과는 각각 해당 범위의 근거로 기록한다.

한 요구의 지위가 바뀌면 같은 ID에 변경일, 근거, 남은 범위와 연결된 대체 ID를 덧붙인다. 버전 번호가 올라도 미연결·부분 연결 요구는 이 표에 남긴다. 완료 시에는 `요구 ID | 대상 커밋/빌드 | 재현 시드 또는 저장 표본 | 검증한 경로와 결과 | 남은 범위`를 작성한다. 같은 항목을 다음 버전에서 다룰 때는 이 ID를 참조한다.

## 3. 설정과 실제 효과 대조표

자료는 [재능 정의](../../src/data/talents.ts), [가문 정의](../../src/data/births.ts), [출생 코드](../../src/v5/core/birth.ts), [효과와 영입](../../src/v5/core/fx.ts), [회복](../../src/v5/core/health.ts), [위험](../../src/v5/core/risk.ts), [전투 유닛](../../src/v5/core/fight.ts)이다. 공용 엔진에 소비 코드가 있더라도 현행 주인공 경로가 값을 넘기는지 확인한다.

| V7-11I | 가난한 집안 `poor` | 대체 후보. v5 신규 추첨에서 제외되며 초기 돈은 집안 형편 규칙에서 설정된다. | **대체.** 신규 노출은 집안 형편으로 관리한다. 저장 ID와 과거 설명이 나타나는 경우 현행 집안 형편으로 표시한다. |
| V7-11J | 악마의 열매 각성 | 부분 연결. 현행 전투는 열매 효과 계산에 `awakened=false`를 넘기며 공용 코드에는 각성 효과가 있다. | **포함 제안, 첫 생애 뒤 확장.** 열매 보유·충분한 숙련·지정 사건·실전 효과를 검증한다. 열매가 없는 경로의 꿈과 전성기는 그대로 완료 가능해야 한다. |

신규 특성은 데이터 ID, 효과의 소비 위치, 잠금 또는 적용 안내, 구저장 처리, 검증 시드의 다섯 칸을 갖춘다. 가문 유래의 조건을 표기할 때 비밀 성씨를 유추할 이름이나 가계는 공개하지 않는다. 성장 경지 이름과 전투 효과는 같은 자격 판정에서 읽는다.
