# 01 아키텍처

새 버전의 이름은 **v4.0.0**이다. v3.x 폴더는 건드리지 않는다.

## 1. 기술 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript | 상태와 데이터의 형태를 컴파일 때 검사한다. v3.3.3의 결함 대부분이 형태 불일치였다 |
| 빌드 | Vite | 여러 파일로 개발하고 정적 파일로 내보낸다 |
| 화면 | Preact | 상태가 바뀌면 화면이 따라 바뀐다. 3KB라 가볍다 |
| 테스트 | Vitest | 규칙 단위 테스트와 대량 시뮬레이션을 같은 도구로 돌린다 |
| 스타일 | 일반 CSS + CSS 변수 | v3.4.0 시안의 픽셀 스킨을 옮긴다. Tailwind는 쓰지 않는다 |
| 글꼴 | Galmuri, Press Start 2P | 저장소에 넣어 직접 제공한다. 외부 CDN에 기대지 않는다 |
| 배포 | GitHub Pages | 정적 파일만 올린다. 서버가 없다 |

## 3. 모듈 경계

```
ui ──▶ app ──▶ core ──▶ data
              (core는 ui, app, 브라우저를 모른다)
```

| 규칙 | 내용 |
|---|---|
| core는 순수하다 | DOM, 타이머, localStorage, `Math.random`, `Date`를 쓰지 않는다. 입력은 상태와 명령, 출력은 새 상태다 |
| 한 규칙은 한 곳에 | 같은 계산을 두 곳에 두지 않는다. 기존 함수를 덮어쓰는 확장을 하지 않는다 |
| 상태는 값만 | 상태에 함수를 넣지 않는다. 그대로 JSON으로 저장되고 되살아난다 |
| 효과는 데이터 | 선택지, 임무, 전투 결과의 효과는 `{op, …}` 목록이다. 적용기는 하나다 |
| 수치는 한 파일 | 계수, 확률, 속도는 `data/balance.ts`에 모은다. 규칙 코드에 숫자를 직접 쓰지 않는다 |
| 난수는 상태 안에 | 난수의 씨앗과 진행 위치를 상태에 둔다. 같은 씨앗과 같은 입력이면 같은 인생이 나온다 |

## 4. 상태가 바뀌는 길

화면은 상태를 직접 고치지 않는다. 명령을 보낸다.

```
화면(버튼) ─ 명령 ─▶ store ─▶ core.reduce(state, command) ─▶ 새 상태 ─▶ 화면 다시 그림
타이머     ─ tick ─▶
```

| 명령 | 뜻 |
|---|---|
| `tick` | 한 달이 흐른다 |
| `answerChoice` | 중대한 선택에 답한다 |
| `confirmPrep` | 강적 준비를 마치고 전투를 시작한다 |
| `intervene` | 집단전에서 누구를 도울지 정한다 |
| `ackBattle` | 전투 결과를 확인한다 |
| `saveLoadout` | 평소 교전에 쓸 편성을 바꾼다 |
| `equip`, `buy`, `sell`, `appraise`, `treat` | 장비, 상점, 감정, 치료 |
| `newLife`, `endLife` | 새 인생, 결산 확인 |

### 멈춤 — 한 곳에서만 정한다

v3.3.3의 진행 불가 결함 4건은 "지금 멈춰야 하는가"를 여러 깃발로 따로 관리해서 생겼다. v4는 깃발을 두지 않는다. 상태에 **대기 중인 일**이 하나 있으면 멈추고, 없으면 흐른다.

```ts
type Pending =
  | { kind: 'choice'; … }      // 중대한 선택
  | { kind: 'prep'; … }        // 강적 준비
  | { kind: 'battle'; … }      // 전투 관전 · 결과 확인
  | { kind: 'intervene'; … }   // 집단전 개입 선택
  | { kind: 'ending'; … }      // 결산
  | null
```

- `tick`은 `pending`이 `null`일 때만 받아들인다.
- 화면은 `pending.kind`를 보고 띄울 창을 정한다. 창을 닫는 길은 그 `pending`을 끝내는 명령뿐이다.
- 관리용 창(기술 트리, 도감, 저장)은 `pending`이 아니다. 열려 있는 동안 타이머만 멈춘다.
- `pending`은 상태의 일부라 저장했다 불러와도 그대로 이어진다.

## 5. 테스트와 검사

| 종류 | 내용 |
|---|---|
| 단위 테스트 | 피해 공식, 자연계 감소, 숙련 상승, 선택 발생 간격, 효과 적용, 조건 판정 |
| 불변 조건 | 어떤 명령 뒤에도 성립해야 하는 것. 체력은 0 이상, `pending`이 있으면 `tick`이 무시됨, 참조하는 기술·인물이 존재함 |
| 대량 시뮬레이션 | 무작위로 답하는 인생 수천 번을 끝까지 돌린다. 멈추는 인생이 없어야 한다 |
| 데이터 검사 | 끊긴 참조, 열 수 없는 기술, 조건이 영영 맞지 않는 선택, 보상 없는 임무를 찾는다 |
| 브라우저 확인 | 새 인생부터 결산까지 직접 플레이. 1360px, 390px |

대량 시뮬레이션에서 볼 지표는 [05_성장과_콘텐츠.md](05_성장과_콘텐츠.md) 8장에 있다.

## 6. 배포

- `npm run build`가 `dist/`에 정적 파일을 만든다.
- GitHub Actions가 `main`에 올라온 것을 빌드해 GitHub Pages에 올린다.
- 첫 화면과 정보 창에 비영리 팬게임임을 밝힌다. 원작 그림과 음원, 시판 게임에서 추출한 그림은 저장소에 넣지 않는다. `refer/` 폴더는 저장소에 올리지 않는다.
