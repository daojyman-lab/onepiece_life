## 2. SoundFX — Web Audio 신시사이저 (L772~828)

### 구조
- `enabled: true` (기본 켜짐), `ctx: null` (지연 생성).
- `init()` (L775~780): `ctx`가 없을 때만 `window.AudioContext || window.webkitAudioContext`로 생성. 둘 다 없으면 아무것도 안 함.
- `play(type)` (L781~827):
  1. `enabled`가 false면 즉시 return(음소거).
  2. `try { ... } catch (e) {}` 로 전체를 감싸 오류를 삼킴.
  3. `init()` 호출 → `ctx` 없으면 return.
  4. `ctx.state === 'suspended'`이면 `ctx.resume()` (브라우저 자동재생 정책 대응. 최초 `play`가 버튼 클릭 핸들러 안에서 불리므로 사용자 제스처로 컨텍스트가 시작됨).
  5. 호출마다 `OscillatorNode` 1개 + `GainNode` 1개를 만들어 `destination`에 연결. 노이즈/필터/리버브 없음. 단일 오실레이터의 주파수 계단 변화로 멜로디 표현.
- 별도의 볼륨 설정, 저장(localStorage) 연동은 없음. `enabled`는 세이브에 저장되지 않는 런타임 값.

### 효과음 4종 (함수가 아니라 `play(type)`의 type 문자열)

| type | 파형 | 주파수(Hz) 시퀀스 | 시작 게인 | 길이 | 용도(호출처) |
|---|---|---|---|---|---|
| `tick` | triangle | 520 | 0.03 → 0.001 (지수 감쇠) | 0.05초 | 퀴즈 선택지 클릭(L4238), 해가 바뀔 때(월>12 → 나이+1, L2924) |
| `event` | square | 440 → 660(+0.08s) | 0.07 → 0.001 | 0.24초 | 주요 사건 팝업 발생 `triggerMajorEvent`(L2023), 퀴즈 시작 버튼(L4347), 퀴즈 건너뛰기 버튼(L4351) |
| `treasure` | sine | 587.33 → 880(+0.09s) → 1174.66(+0.18s) | 0.08 → 0.001 | 0.35초 | 보물·아이템·열매 획득, 동료/형제 합류, 패기 체득, 특훈 완료, 선박 개조, 결투 승리 (L2050, 2069, 2286, 2347, 2468, 2514, 2565, 2612, 2630, 3549, 3741, 4104) |
| `danger` | sawtooth | 220 → 165(+0.12s) | 0.08 → 0.001 | 0.30초 | 참패 선택지(L2773), 사망 처리(L3003), 결투 패배(L4104) |

- 알 수 없는 type을 넘기면 오실레이터가 start되지 않고 무음(분기 없음).
- 음소거 토글(L4489~4491): `#btnSoundToggle` 클릭 시 `SoundFX.enabled` 반전, 버튼 라벨 `"🔊 효과음"` ↔ `"🔇 음소거"`.
- BGM 없음.

## 4. PERSONALITY_QUESTIONS — 성격 질문 풀 60문항

### 4.1 문항 스키마 (L1071~)

```
{ id: number, cat: string(분야), q: string(상황 지문),
  a: [ { t: string(선택지 문구), trait: string(성향), stat: {능력치키: 가산치} } × 3 ] }
```
- 모든 문항이 **3지선다**.
- `trait` 9종: 모험형, 분석형, 중재형, 돌파형, 수호형, 야망형, 독립형, 자유추구형, 충성형.
- `stat` 키 8종: str, spd, int, vit, lead, sense, luck, haki. (exp, dfMastery는 퀴즈로 오르지 않음)
- 선택지당 가산 합계: 수기 20문항은 2~4점(대부분 3점: 2+1 / 3 단독. 4점은 Q6의 "vit 2, haki 2", "str 2, haki 2"와 Q17의 "vit 2, haki 2". 2점은 Q1의 "lead 2"), 자동 40문항은 전부 3점(2+1).

### 4.2 출제 규칙 (L4207~4220, L4222~4249)

- **한 판에 10문항** 출제: `quizQueue = shuffled.slice(0, 10)` (L4211).
- 풀: `PERSONALITY_QUESTIONS` 중 `recentQuestionIds`에 없는 것. 풀이 10개 미만이면 전체 60문항에서 뽑음(L4209~4210). 셔플은 `sort(() => Math.random() - 0.5)`.
- 출제된 id를 `recentQuestionIds`에 push. 길이가 40 초과면 가장 오래된 20개 제거(L4212~4213). → 같은 브라우저 세션에서 연속 새 게임 시 최근 3~4판 문항이 재출제되지 않음. `recentQuestionIds`는 모듈 변수라 새로고침하면 초기화(저장 안 됨).
- 선택지 순서도 매번 셔플(L4231). 버튼 라벨 `"1. ..."`.
- 진행 표시: `"분야: {cat}"`, `"문항 n / 10"`, 진행 바 %(L4224~4226).
- 이름 미입력 시 `"사용할 이름을 입력해 주세요."` 토스트 후 중단(L4208).
- **퀴즈 건너뛰기**(L4350~4354): `quizAnswers = []`로 두고 바로 생성 → 성향은 기본값 "모험형", 퀴즈 보정 0.

### 4.3 결과 집계 (L4251~4275)

- `traitCounts[trait]++`, `bonusStats[k] += v` 누적.
- 대표 성향 = 최다 득표 trait. 동점이면 **먼저 답한 쪽**(엄격한 `>` 비교, 객체 삽입 순서). 답이 없으면 "모험형".
- 누적 `bonusStats`는 생성기에서 초기 능력치에 그대로 더해진다(L1672~1674). 10문항 기준 총 가산 약 30점(20~40 범위).
- `player.trait`의 이후 소비처는 미확인(담당 범위 밖).

### 4.5 자동 생성 40문항 (id 21~60) (L1175~1200)

- `EXTRA_QUESTION_TEMPLATES` 10개: `[cat, q, 선택지1, 선택지2, 선택지3]`
- 생성 루프 `i = 0..39`: `tpl = TEMPLATES[i % 10]`, `id = 21 + i`.
- 지문 접미사: `i < 10`이면 없음, `i >= 10`이면 `" (상황 N)"`, N = `floor(i/10)+1` → id 31~40은 "(상황 2)", 41~50 "(상황 3)", 51~60 "(상황 4)".
- 즉 **실질 고유 문항은 10개이며 각 4회 복제**(지문 접미사만 다름). 한 판(10문항)에 같은 템플릿이 최대 4번 나올 수 있다.
- 선택지별 성향·보정은 템플릿과 무관하게 **위치로 고정**:
  - 선택지1: `i` 짝수 → 돌파형, 홀수 → 모험형 / stat `str 2, haki 1`
  - 선택지2: `i` 짝수 → 분석형, 홀수 → 자유추구형 / stat `int 2, spd 1`
  - 선택지3: `i` 짝수 → 수호형, 홀수 → 야망형 / stat `lead 2, vit 1`
  - `i % 10`과 `i`의 홀짝이 같으므로 템플릿별 성향 세트는 4회 복제 모두 동일.

- 플레이어 전투력 공식 `getCombatBreakdown` (L1885~1908, 능력치 소비처로서 기록):

  - healthScore = round(vit × 1.5 + health × 0.45)
  - healthFactor = max(0.4, health / maxHealth)
  - total = round(합계 × (0.7 + 0.3 × healthFactor))
  - lead, sense, luck은 전투력 합계에 들어가지 않음(luck은 `luckStat`으로 따로 반환).
  - 기본 초기값(보정 0, 체력 100)으로 계산하면: 26+24+20+0+24+9+(18+45)=166 → total 166.

### 7.3 생성 순서와 규칙

1. **기본 설정** (L1645~1649): `createEmptyState()` → name(trim, 빈 값이면 이름 풀), gender, trait(`dominantTrait || "모험형"`), lifeGoal "unassigned".
2. **성씨 추첨** (L1652~1653): `allowedGender`에 성별이 포함된 성씨 중 균등 1개. rarity 가중 없음.
3. **파생 필드** (L1655~1664): surname, hasD, fullName(`"성 D. 이름"` 또는 `"성 이름"`), species, birthplace(균등), location = birthplace, household(균등), surnameLore.
   - `locationId`는 건드리지 않아 **항상 "east_foosha"**.
4. **능력치 공식** (L1667~1675) — `stats`의 10개 키 전부에 대해:

   `초기값 = 기본값 + randInt(0, 4) + (성씨 bonusStats[k] || 0) + (퀴즈 bonus[k] || 0)`

   - exp, dfMastery에도 randInt(0,4)가 붙는다 → exp 5~9, dfMastery 0~4로 시작.
   - `bonusStats[k]`가 0이거나 없으면 가산 없음(truthy 검사). 음수(-2)는 적용됨(재규어 spd).
   - 예: 재규어(거인족) str = 10 + 0~4 + 14 = 24~28(+퀴즈), spd = 10 + 0~4 − 2 = 8~12(+퀴즈).
   - 종족·출생지·가문 자체의 능력치 보정은 없음(성씨 bonusStats에 통합되어 있음).
5. **시작 능력 / 악마의 열매** (L1678~1693):
   - `abilities = []`로 초기화 후, 성씨에 `guaranteedAbility`가 있으면 추가.
   - `Math.random() < 0.22` **그리고** 종족이 "어인족"이 아니면: `DEVIL_FRUITS_POOL`에서 균등 1개 → `devilFruit = name`, abilities에 `"악마의 열매: {name}"` 추가, `df.bonus`를 stats에 가산(`(stats[k] || 10) + v`).
   - 그렇지 않으면(78%, 어인족은 100%): `TALENT_POOL`에서 균등 1개를 중복이 아니면 추가(1/7 확률로 "없음 (순수 노력파)").
   - 즉 열매와 추가 재능은 **배타적**. 확정 능력 + 열매, 확정 능력 + 재능 조합은 가능.
6. **소지금/소속 예외** (L1695~1701):
   - 종족이 "천룡인" → money 250,000, affiliation "세계귀족(천룡인)", roleTitle "성지의 후예".
   - 아니고 household에 "해군" 포함("해군 집안", "전직 해군 거인 집안") → money 35,000.

### 8.2 `normalize(s)` 가 하는 일 (L5484~5518)

1. **방어적 보정**: `s.meta`, `s.family`, `family.parents`, `family.siblings`가 없으면 빈 값으로 생성.
2. **인물 이름 정규화**(인물당 1회, `identity333` 플래그로 재실행 방지). 대상: 가족이거나 원작 인물이 아닌 인물.
   - 원작 인물 판정 `isCanon(r)`(L5483): `r.isCanon`이 참 / id가 `rel_ace`, `rel_teach`, `rel_bonclay`, `rel_hachi_surprise` 중 하나 / (id가 `rel_local_mentor`, `rel_child_rival`, `rel_father`, `rel_mother`가 아니면서) 이름이 CANON 정규식에 걸림.
   - 가족(`family`에 있거나 `category === 'family'`): 이름이 `"{플레이어 성씨} "`로 시작하지 않으면 앞에 붙임. `r.surname = 플레이어 성씨`.
   - 비가족·비원작: `surname`이 없을 때, 이름에서 끝의 "노인"을 떼어낸 뒤 공백이 없으면 SURNAMES에서 무작위 성씨를 뽑아 `"{성씨} {이름}"`으로, 공백이 있으면 첫 단어를 `surname`으로 기록.
   - `r.name = r.fullName = 새 이름`, `identity333 = true`. 이름이 바뀌면 (구→신) 목록에 기록.
3. **악마의 열매 구체화**: 인물의 `abilityType/combatStyle/specialty/lifeRecord`에 "악마의 열매 능력" 또는 "불안정한 열매 능력"이 있거나 `devilFruit`이 있으면 `fruitFor(s, r)` 호출(L5476~5482).
   - 이미 `devilFruit`이 있으면 FRUITS → DEVIL_FRUITS_POOL(이름 일치 또는 괄호 앞부분 포함) 순으로 찾아 설명을 붙임. 못 찾으면 `{ name, type: '', desc: r.fruitDescription || '능력의 활용 범위는 수련과 경험에 따라 넓어진다.' }`.
   - 없으면 FRUITS 중 **플레이어와 모든 관계 인물이 쓰지 않는 것**에서 무작위 배정(중복 방지). 8종이 다 쓰였으면 null.
   - 배정 성공: `devilFruit, fruitDescription, fruitType, abilityType = 열매명, combatStyle = "{열매명} · {계통}"`, 그리고 `specialty/firstMet/recentEvent/lifeRecord/secret`의 범용 문구를 `"{열매명} — {설명}"`으로 치환.
   - 배정 실패(null): `abilityType = '없음'`, `combatStyle = '도구 운용'`, 범용 문구를 "밧줄과 구조 도구를 활용한다"로 치환.
4. **가족 참조 복구**: `family.parents/siblings`의 각 항목을 `relationships.list`의 같은 id 객체로 교체(JSON 불러오기 후 사본이 분리되는 문제 대응 — 주석 L5507).
5. **개명 전파**: 개명이 있었으면 모든 인물의 `firstMet/recentEvent/lifeRecord/secret`과 로그 항목의 `text/message/body`에서 옛 이름을 새 이름으로 치환(이미 새 이름인 부분은 보존하는 split/join 방식, L5510).
6. **`family.householdHistory` 생성**: 부모별 `"{relType} {name} · {combatStyle || specialty}{ · fruitDescription}"`을 `" / "`로 연결.
7. **플레이어 열매 표기**: `player.devilFruit`이 DEVIL_FRUITS_POOL 또는 FRUITS에 있으면 `player.fruitDescription = desc`, abilities에서 `"악마의 열매:"`로 시작하는 항목과 `"{열매명} —"`로 시작하는 항목을 지우고 `"{열매명} — {desc}"`를 추가.
8. `meta.version = 'v3.3.3'`.

## 9. 발견한 버그 · 불일치 · 중복 데이터

### 데이터가 정의만 되고 쓰이지 않는 것
1. `SURNAME_DB[].rarity`("일반/희귀/전설")는 어디서도 읽지 않는다. 전설 성씨(몽키, 골, 돈키호테)도 다른 성씨와 같은 확률로 나온다.
2. `DESTINATIONS_DB[].minAge`는 참조가 없다. 값(1~18)은 해금 나이처럼 보이지만 실제로는 제한이 걸리지 않는다(원본 목적지 UI 기준, L3759~3777).
3. `CANON_BOUNTY_BOARD[].power`는 참조가 없다. 전투는 `BATTLE_OPPONENTS_DB.power`(다른 척도)를 쓴다.
4. `player.hidden.diseaseResist`는 초기값 정의(L1548) 외 참조를 찾지 못했다(투자처 medical의 설명은 "질병 저항 상승"이라고 적혀 있음).
5. `DEVIL_FRUITS_POOL[].bonus`는 캐릭터 생성 시에만 적용되고, 게임 중 열매 획득 이벤트(L2062~2066, L2620~2624)는 열매와 무관한 고정 보정을 준다.
6. 모듈 변수 `selectedLifeGoal = "pirate_king"`(L1507)은 생성기에 전달되지 않는다.

### 조건 문구(reqText)와 실제 판정(check)의 불일치 — LIFE_AMBITIONS_DB
7. pirate_king 4단계: 문구는 "15억 베리 이상 **&** 사황급 결투 승리", 판정은 **OR**.
8. pirate_king 1·2단계: 문구는 현상금/강적 격파, 판정은 `exp >= 25` / `exp >= 60`만으로도 통과.
9. swordsman 1단계: "검술 특기 보유"는 판정에 없음(str·spd만).
10. swordsman 2단계: `items`에 "검" 또는 "도"가 포함된 문자열이 있으면 통과인데, 시작 아이템 **"고향의 나무 단검"에 "검"이 들어 있어** 사실상 `exp >= 40`만 요구한다.
11. swordsman 3단계: "대검호급 강적 격파"는 판정에 없음(`exp >= 85`로 대체).
12. fleet_admiral 2단계: 문구 "스피드·**지능** 28 이상", 판정은 spd만 확인(int 미검사).
13. fleet_admiral 3단계: "대장 진급 결투 승리"는 판정에 없음(전투력 320만).
14. revolutionary 3단계: "CP9/정부 특무부대 격파"는 판정에 없음.
15. revolutionary 2단계 check만 인자 `p`가 아닌 전역 `G`를 직접 참조한다(다른 상태 객체로 호출하면 결과가 어긋날 수 있음).

### 생성기 관련
16. `locationId`가 출생지와 무관하게 항상 `"east_foosha"`다. 와노쿠니·어인섬·마리조아 출생이어도 목적지 화면에서는 후샤 마을이 "현재 체류 중"으로 표시된다. `location`(문자열)과 `locationId`가 어긋난 채 시작.
17. 주석은 "Generate 1~3 Siblings"(L1763)인데 실제로는 35% 확률로 0명.
18. 손아래 형제의 나이가 1로, 1세인 플레이어와 같다(둘째·셋째는 항상 "동생"인데 동갑).
19. 소꿉친구 이름은 플레이어·형제 이름 제외 필터가 없어 같은 이름이 나올 수 있다.
20. 소꿉친구 `gender`는 남/여 무작위인데 `firstMet` 문구는 항상 "소년".
21. 여인섬(보아) 출생이면 형제는 전원 여성이지만, `siblingPaths`·`dream` 문구는 "형제"로 고정.
22. `stats` 전체 키 루프라 `exp`, `dfMastery`에도 0~4 무작위가 붙는다(열매 없이 dfMastery > 0으로 시작 가능).
23. 전투력 공식의 `(s.dfMastery || 10)`: dfMastery가 0이면 10으로 취급되어, 숙련 0인 능력자가 숙련 1~9보다 높게 계산된다(0 → 97점, 1 → 77점).
24. 빈 이름 폴백(`pick(FIRST_NAMES_POOL)`, L1646)은 UI가 빈 이름을 막아 도달 불가(죽은 분기).
25. 천룡인 분기가 `else if`의 앞이라, 천룡인은 household와 무관하게 250,000 베리(의도로 보이나 기록).

### 질문 풀 관련
26. "60문항"은 실질적으로 수기 20 + 템플릿 10종 × 4회 복제다. 복제본은 지문 끝 "(상황 2~4)"만 다르고 선택지·보정이 동일하며, 한 판에 같은 템플릿이 여러 번 나올 수 있다(주석 "60 distinct questions"와 불일치).
27. 자동 40문항은 선택지 내용과 무관하게 위치별로 성향·보정이 고정이라 문구와 성향이 맞지 않는 경우가 있다. 예: "해군 대장의 포위" 선택지1 "전원 철수 명령을 내리고 퇴로를 뚫는 데 집중한다." = 돌파형/str+2·haki+1, "식량 위기" 선택지1 "내 몫의 물까지 동료들에게 나누어 주고 버틴다." = 모험형/str+2·haki+1, "해왕류 조우" 선택지3 "패기의 기백으로…" = lead+2·vit+1(haki 없음).
28. 풀의 2/3가 자동 문항이므로 한 판 보정이 str/int/lead 쪽으로 쏠리고, 중재형·독립형·충성형은 수기 문항에서만 나온다(중재형 3, 충성형 3개 선택지뿐).
29. 성향 동점 처리 규칙이 명시적이지 않다(먼저 답한 성향이 이김).

### 목적지·원작 인물 데이터
